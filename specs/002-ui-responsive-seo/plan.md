# Implementation Plan: UI Polish, Responsive Hardening & SEO

**Branch**: `002-ui-responsive-seo` | **Date**: 2026-06-02 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/002-ui-responsive-seo/spec.md`

## Summary

Layer SEO/social discoverability, full-breakpoint responsive hardening, and in-system visual polish onto the shipped personal-site MVP. No new sections, no redesign. Work concentrates in the App Router metadata layer (`layout.tsx`, new `sitemap.ts` / `robots.ts` / `opengraph-image`, JSON-LD), the Tailwind v4 token/spacing scale in `globals.css`, and pass-by-pass refinement of the seven existing section components. The site stays statically generated on Vercel with zero server runtime — all SEO routes (sitemap, robots, opengraph-image) and the structured data are produced at build time.

## Technical Context

**Language/Version**: TypeScript 5 / Node 20

**Primary Dependencies**: Next.js 16.2.6 (App Router), React 19.2, Tailwind CSS v4, Framer Motion 12, Geist font (`geist` package). Optional dev-only: `schema-dts` (JSON-LD types — can be hand-typed instead).

**Storage**: N/A — content remains in `src/data/` TypeScript constants. SEO config (production URL `https://www.jmontenegro.dev`, profile links) lives in a `src/data/site.ts` constant.

**Testing**: N/A — no test suite. Verification is manual: Lighthouse/SEO audit, social-card debuggers, and a breakpoint visual pass.

**Target Platform**: Modern browsers, 320px → 2560px screens, dark mode only.

**Project Type**: Static web app (SSG via Vercel).

**Performance Goals**: LCP < 2.5s on typical mobile, CLS < 0.1, no render-blocking JS for above-the-fold content. Animations ≤ 0.6s (unchanged from MVP).

**Constraints**: No server runtime in production (SSG only). No light mode. No new colors/fonts. No inline styles, no CSS Modules. Single social preview image. English single page.

**Scale/Scope**: 1 page, 7 existing sections, ~3 new metadata route files, ~1 site-config data file, token/spacing additions. Single developer.

**Structure Decision**: Single Next.js project, unchanged topology. SEO is added via App Router file conventions (`sitemap.ts`, `robots.ts`, `opengraph-image.png`) plus an expanded `Metadata` export in `layout.tsx` and a JSON-LD `<script>` in `page.tsx`. A single new `src/data/site.ts` centralizes the production URL and profile links so metadata, structured data, sitemap, and robots share one source of truth. Visual/responsive work is in-place refinement of existing components and `globals.css` tokens — no new components unless a refinement is reused by ≥2 sections.

## Implementation Phases

### Phase A — Site Config Foundation
1. Create `src/data/site.ts`: production URL, author name, title, description, profile links (LinkedIn, GitHub, email), default OG image path.
2. Add `metadataBase: new URL(site.url)` and `alternates.canonical: "/"` to `layout.tsx`.

### Phase B — Metadata & Social Cards
3. Expand `layout.tsx` `metadata`: `openGraph` (title, description, type `website`, url, siteName, locale `en_US`, images), `twitter` (`summary_large_image`, title, description, images), and keep `lang="en"`.
4. Add a branded `src/app/opengraph-image.png` (1200×630, dark theme + cyan accent + Geist). Confirm Next auto-emits `og:image` tags with dimensions.
5. Add JSON-LD `Person` schema as a static `<script type="application/ld+json">` in `page.tsx`, fed from `site.ts` (name, jobTitle "AI Engineer", url, sameAs profile links), XSS-escaped.

### Phase C — Crawlability
6. Create `src/app/robots.ts` → `MetadataRoute.Robots`: allow `*`, reference `${site.url}/sitemap.xml`.
7. Create `src/app/sitemap.ts` → `MetadataRoute.Sitemap`: single entry for canonical URL with `lastModified`.
8. Verify `next build` emits static `/robots.txt`, `/sitemap.xml`, and `/opengraph-image` — no runtime.

### Phase D — Responsive Hardening
9. Audit every section at 320 / 375 / 768 / 1024 / 1440 / ≥2560px; log overflow, clipping, cramped spacing, small tap targets.
10. Fix horizontal overflow and clipping (FR-010); ensure tool-tag wrapping and avatar scaling hold at 320px.
11. Enforce min tap-target sizing on Header nav, contact links, tags (FR-011); verify legible type without zoom (FR-012).
12. Constrain max content width on ultra-wide; verify portrait↔landscape reflow (FR-013, FR-014).

### Phase E — Visual Polish (within design system)
13. Add a spacing/rhythm scale to `globals.css` `@theme`; apply consistent vertical section rhythm (FR-018).
14. Normalize typographic hierarchy in `SectionHeading` + section bodies — title / eyebrow (mono) / body (FR-019).
15. Add consistent `:focus-visible` and hover feedback for all interactive elements (FR-020, FR-024).
16. Verify zero design-system drift: no new colors/fonts, no light mode (FR-021).

### Phase F — Accessibility & Performance
17. Add descriptive `alt` to all meaningful images; verify semantic landmarks + heading order (FR-022, FR-023).
18. Verify contrast of text/interactive elements on dark bg (FR-025).
19. Confirm avatar + OG image dimensions prevent CLS; measure LCP < 2.5s, CLS < 0.1 (FR-015, FR-016, SC-004).

### Phase G — Verification & Deploy
20. `next build` — zero errors (SC-008).
21. Run an SEO/Lighthouse audit on the build; confirm no missing critical metadata (SC-006).
22. Validate social cards on LinkedIn / Slack / X debuggers (SC-001), search snippet preview (SC-002).
23. Keyboard-only pass — visible focus, no traps (SC-005); breakpoint visual pass 320→1440 (SC-003).
24. Push to `main` → Vercel deploys.
